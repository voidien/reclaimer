## Recovering an old shell copy
- The owner's rule: the picker offers it. An old copy that stands refused tells its owner's list where it is. Once a link has looked where the list said and found nothing, the picker shows "old copy, recover?" with a second click to confirm, so a healthy shell stays pickable. `ShellRecovery` loads the newer copy's chunks first: a shell that is still there is left alone. Otherwise the old copy takes a number above the list's and is the shell; a lost copy that turns up later gives way to it. Tests: `anOldCopyComesBackWhenTheNewerOneIsLost`, `recoveryLeavesAHealthyShellAlone`, `recoveryOfACopyThatHasGoneChangesNothing`, `recoveryAsksForASeatInReachAndNoOutbox`, `aLinkDuringTheWaitEndsRecovery`, the restart test `anOldCopyIsRecovered` with two real saved states, and the list through a save.

## Known issues
- **A newer copy that moved from where the list says** cannot be found by recovery. If it loads later it loses to the recovered copy and is gone. That is the owner's choice, and the confirmation warns of it.
