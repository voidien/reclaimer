## Remote control: the shell list
- The player file now keeps one entry per shell for good (`LinkState.KnownShell`: newest link number, last place, wreck, gone). It closes two gaps the review found: a stale copy that turns up after its outbox has ended now removes itself, and a shell or an emptied wreck destroyed for good cannot come back. `/void_reclaimer link shells <player>` prints the list. Tests: `LinkLedgerGameTests` (10) and four in `LinkStateTest`, all mutation-checked.
- Review fixes: two copies of a shell can load together after a crash, and the level keeps the first and refuses the second, which then vanishes at the next save. If the older came first, it removed itself as stale and the newer was gone with it: a whole body lost. `Links.onEntityJoin` now settles the clash as the second copy arrives, the newer stays, with or without the owner, and an old copy removes itself only when the newer body is proven or the shell is gone (`Links.replaced`) (`aNewerShellWinsAClash`, a restart test, on CI; two more in `LinkLedgerGameTests`). Also: an old copy dying changes nothing on record, a link cannot lower the list's number, a wreck that is gone cannot be salvaged again, one bad entry costs only that entry (with a log line), emptying a wreck saves to `level.dat` too, and a throw while putting a shell back no longer stops a wake.
- Saves from before this have no entries; an outbox still running hands over to the list when it ends.

## Known issues
- **A clash with a copy in a chunk that is unloading** cannot be seen, so the level refuses the newer copy and it is lost. It needs a crash and that exact moment. The older copy then stays as a rollback: it no longer removes itself on the list's word alone. It also takes no link, so getting that body back would need a command (none yet).
- **An old copy can stay visible:** in another dimension, or until the newer copy's chunk loads, an old copy stands in the world and refuses links.
- **A shell destroyed with its owner offline** can still come back from a running outbox: the list is in the player file, so it cannot hear of it. Only a dedicated server can reach this.
